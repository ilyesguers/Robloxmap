# 🤖 بوت تيليجرام — لايكات فري فاير **حقيقية ومحتسبة** (إعادة بناء أغسطس 2026)

بوت تيليجرام (Python + aiogram 3 + aiohttp) يرسل إعجابات **تُحتسب فعلياً**
على بروفايلات فري فاير — عبر مخزون **حسابات حقيقية بمستوى 8+** يتحقق منها
البوت (دخول + مستوى + حظر) قبل قبولها، مع كشف تلقائي لسيرفر الهدف، وبحث
بالاسم، وتقارير بأرقام **المحتسب في اللعبة** وليس مجرد «أُرسل».

---

## 🔴 لماذا أُعيد بناء البوت؟ (تشخيص أغسطس 2026 — اقرأها)

النسخة القديمة كانت تنشئ **حساب ضيف جديد (مستوى 1) لكل إعجاب**. كانت تقول
«أُرسل 100 إعجاب ✅» ولا يزيد شيء في اللعبة، والحسابات لا تظهر في البحث.

**السبب المؤكد:** منذ تحديث **OB51 (أبريل 2026)** فرضت Garena «بوابة مستوى»:

| مستوى المرسل | مصير الإعجاب |
|---|---|
| 1 – 7 | ❌ يتجاهله السيرفر **صامتاً** (الواجهة ترد 200 وكأنه نجح!) |
| 8 – 20 | ⚠️ يُحتسب حتى **~20 إعجاباً يومياً فقط** لكل هدف |
| **22+** | ✅ العدد الكامل (~100 يومياً) ممكن |

وهذا موثّق من مجتمع المطورين نفسه: مالك أكبر مستودع مفتوح للموضوع
(kaifcodec/freefire-like-and-guest-api) أوقف المشروع بعد OB51 للسبب نفسه،
وخدمة HL Gaming وثّقت تجريبياً سقف الـ 20 إعجاباً من حسابات 8-20 (مايو 2026).

**الخلاصة:** لا توجد طريقة لجعل حسابات مستوى 1 تُحتسب — أي بوت يعدك بذلك
يكذب عليك بالأرقام. الطريقة الوحيدة الشغالة في 2026 = **حسابات حقيقية
بمستوى 8+** (أنشأها ولعب بها بشر)، وهذا ما بني عليه هذا البوت.

## 🔄 كيف يعمل الآن؟

```
المستخدم يرسل UID (أو يبحث بالاسم)
      │
      ▼
1) كشف تلقائي للسيرفر + قراءة البروفايل (اسم/مستوى/لايكات حالية)
      ▼
2) فحص المخزون المتاح للهدف: حسابات status=ok بمستوى ≥ 8
   لم تُعجب بهذا الهدف خلال آخر 20 ساعة
      ▼
3) لكل إعجاب: دخول حقيقي بالحساب (Token Grant → MajorLogin → JWT)
   مع كشف الحظر تلقائياً (الحقل 12) وإقصاء الحسابات الميتة
      ▼
4) تحقق حي أثناء الإرسال: قراءة العداد كل 5 إعجابات،
   وتوقف مبكر ذكي إذا ثبت العداد (وفرنا عليك المحاولات الميّتة)
      ▼
5) 📈 تقرير النهاية: قبل ← بعد (+المحتسب فعلياً ✅)
```

### الحسابات الضيفية الجديدة؟
تُستخدم فقط كـ«جلسات قراءة» (كشف المنطقة/العداد/البحث) — **لم تعد تُرسل
إعجابات أبداً** لأنها غير محتسبة بتاتاً بعد OB51.

## 🤝 كيف تحصل على حسابات للمساهمة (/donate)؟

من هاتفك (أو محاكٍ):

1. افتح فري فاير ← سجّل الدخول بحساب **ضيف** (Guest) جديد.
2. **العب حتى المستوى 8+** — عادة ~3 مباريات Clash Squad كافية.
   (مستوى 22+ أفضل بكثير: يتجاوز سقف الـ 20 إعجاباً يومياً).
3. أرسل للبوت: `/donate` ثم بالصيغة:
   ```
   UID:كلمة_السر
   ```
   (يقبل حتى 5 أسطر، ويقبل هاش SHA256 الجاهز من أدوات استخراج الضيوف).
4. البوت يتحقق **حقيقياً** (دخول + قراءة مستوى + كشف حظر) ويقبل أو يرفض
   مع السبب — لا حسابات ميّتة في المخزون أبداً.

> 💡 الحسابات المساهَم بها مشتركة: مساهمتك تخدمك وتخدم كل المستخدمين،
> وكل حساب يستطيع الإعجاب بكل هدف مرة كل 20 ساعة.

---

## ⚠️ توقعات صادقة

- لكل هدف: ما يصل إلى **عدد الحسابات المتاحة** في مخزون سيرفره، وما
  يُحتسب فعلاً يعتمد على مستوياتها (سقف Garena الداخلي).
- الحد السحري (~100/يوم للهدف) يتطلب مخزوناً كبيراً من حسابات **22+**.
- الحسابات تُفحص دورياً (`/checkaccounts`) والمحظورة تُقصى تلقائياً.
- البروكسيات مهمة: تسجيل ضيوف القراءة من IP مراكز البيانات غالباً مرفوض.

## 🚀 النشر على Railway

1. **Deploy from GitHub repo** ← اختر المستودع.
2. أضف PostgreSQL: **New ← Database ← Add PostgreSQL**.
3. تبويب **Variables**:
   | المتغير | القيمة |
   |---|---|
   | `BOT_TOKEN` | من @BotFather |
   | `ADMIN_ID` | معرّفك الرقمي (@userinfobot) |
   | `DATABASE_URL` | `${{Postgres.DATABASE_URL}}` عبر **Add Variable Reference** |

   ⚠️ المرجع عبر Reference وليس نسخاً نصياً وإلا ظهر الخطأ
   `socket.gaierror: Name or service not known`.
4. **Redeploy** ← السجلات يجب أن تُظهر `🚀 البوت يعمل الآن...`.
5. فحص حي من Railway Shell: `python tests/live_check.py <UID_تجريبي>`.
6. **الخطوة الأهم:** المخزون يبدأ فارغاً! أضف حساباتك (مستوى 8+) عبر
   `/addaccounts` (للأدمن، حتى 30 سطراً) أو دع المستخدمين يساهمون بـ `/donate`.

## 🧰 أوامر البوت

### المستخدمون
| الأمر | الوصف |
|---|---|
| `/start` | القائمة (أزرار) |
| `/likes <UID>` | إرسال لايكات — السيرفر يُكتشف تلقائياً |
| زر «🔍 بحث بالاسم» | بحث ضبابي بالاسم واختيار الحساب من النتائج |
| `/donate` | مساهمة بحساب ضيف مستوى 8+ (وقود البوت) |
| `/cancel` | إلغاء المهمة الحالية |

### الأدمن
| الأمر | الوصف |
|---|---|
| `/stats` | مستخدمون/طلبات/مرسل vs محتسب/حالات المخزون |
| `/pool` | المخزون حسب السيرفر: العدد، متوسط/أعلى مستوى، حسابات 22+ |
| `/addaccounts` | إضافة دفعية (حتى 30) بتحقق حقيقي + تقرير لكل حساب |
| `/checkaccounts [N]` | إعادة فحص (دخول+مستوى+حظر) للأقدم — إقصاء تلقائي |
| `/broadcast <نص>` | رسالة جماعية |
| `/ban` `/unban` | حظر/فك حظر |
| `/queue` `/clear_queue` | حالة قائمة الانتظار/مسحها |

## ⚙️ متغيرات اختيارية

| المتغير | الافتراضي | الوصف |
|---|---|---|
| `MIN_DONOR_LEVEL` | `8` | أدنى مستوى يُقبل في المخزون (بوابة OB51) |
| `FULL_LIKE_LEVEL` | `22` | مستوى «المرسل الكامل» في التقارير |
| `LIKE_COOLDOWN_HOURS` | `20` | إعجاب واحد لكل حساب/هدف خلال المدة |
| `MAX_LIKES_PER_SESSION` | `100` | سقف الإرسال للجلسة |
| `VERIFY_EVERY` / `STALL_WINDOW` | `5` / `15` | إيقاع التحقق الحي / نافذة التوقف المبكر |
| `MIN_DELAY_SECONDS` / `MAX_DELAY_SECONDS` | `1` / `3` | تأخير عشوائي بين الإعجابات |
| `PROXIES` / `PROXY_API_URL` | فارغ | بروكسيات ثابتة/دوّارة (موصى به) |
| `RATE_LIMIT_HOURS` | `1` | انتظار المستخدم بين الطلبات |
| `DONATE_MAX_LINES` | `5` | سقف أسطر المساهمة الواحدة |
| `DB_CONNECT_RETRIES` / `DB_CONNECT_RETRY_DELAY` | `5` / `3.0` | صمود إقلاعي أمام Postgres |
| `LOG_LEVEL` | `INFO` | مستوى السجلات |

```bash
pip install -r requirements.txt
python tests/smoke_test.py    # سيرفر وهمي يحاكي بوابة المستوى — كلها ✅
python tests/live_check.py    # فحص حي (شغّله من Railway Shell)
```

الـ smoke test يحاكي **السلوك الحقيقي بعد OB51**: واجهة LikeProfile ترد
200 دائماً لكن العداد لا يزيد إلا لمرسل مستوى ≥ 8 — فيثبت أن المحرك
يقيس المحتسب فعلاً ولا أوهام؛ ويغطي كشف المنطقة، البحث بالاسم، قبول/رفض
المساهمات، كشف الحظر، والإلغاء أثناء المهمة.

## 🏗️ هيكل المشروع

```
├── main.py                  # نقطة الدخول
├── config/settings.py       # إعدادات + بوابة المستوى
├── handlers/
│   ├── user.py              # /likes (كشف تلقائي)، بحث بالاسم، /donate، /cancel
│   └── admin.py             # /pool، /addaccounts، /checkaccounts، /broadcast ...
├── middlewares/access_control.py
├── services/
│   ├── garena.py            # عميل Garena: تحقق حسابات، كشف حظر (حقل 12)، بحث، قراءة
│   ├── like_engine.py       # محرك المخزون: كشف منطقة + تحقق حي + تقارير محتسبة
│   ├── pool.py              # التحقق الحقيقي للمساهمات وتخزينها
│   └── database.py          # PostgreSQL: مخزون بمواصفات (level/status/cooldown) + مستخدمون
├── utils/                   # سجلات، تحقق، ثوابت المناطق
└── tests/                   # smoke_test (بوابة المستوى) + live_check
```

## 🛠️ ملاحظات تقنية

- **هياكل protobuf** موثّقة في ترويسة `services/garena.py` (حقول الاستجابة
  الحقيقية: basicinfo=1 {accountid=1, nickname=3, region=5, level=6, liked=21}؛
  blacklist=12 في MajorLogin؛ infos=1 في FuzzySearch).
- أرقام التقارير تأتي من قراءة **GetPlayerPersonalShow** قبل/بعد — وليست
  من عدّاد الإرسال.
- الاستخدام مخالف لشروط Garena (حظر محتمل للحسابات المساهَم بها) —
  ساهم بحسابات ضيفة لا تهمك، ولا تستخدم حسابك الرئيسي أبداً.
